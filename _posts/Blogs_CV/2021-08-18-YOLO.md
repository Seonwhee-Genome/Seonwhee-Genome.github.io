The output of the YOLO network (darknet) is quite original. The input image below is abstracted into a predefined $S \times S$ grid of cells, and the output representation is designed so that each grid cell predicts its information (GT coordinates and class) as $B \times 5 + C$ numbers.<br><br>
<img src="/assets/img_cv/YOLO_input.png" alt="YOLO input" width="250" /><br>
This idea of designing the output representation to fit the task is a good source of inspiration whenever you build something on top of a pre-trained CNN.<br><br>
YOLO uses a single network architecture that divides the image into a grid and, through a single loss function, computes classification and localization for every grid cell in parallel at the same time. This makes it fast to train. <br><br>
<img src="/assets/img_cv/YOLO_figure3.png" alt="YOLO figure3" width="550" /><br>

This is YOLO's architecture for detection. It was inspired by GoogLeNet, but it doesn't actually contain Inception modules; it uses 1x1 reduction layers instead. The architecture was not trained on the detection task directly. It was first pre-trained on ImageNet's 1000-class classification problem, and then trained for detection.<br><br>

Pre-training used the first 20 conv layers of the architecture above, with one average pooling layer and one fully connected layer attached (figure below), and ran for about a week.<br>
<img src="/assets/img_cv/YOLO_figure3a.png" alt="YOLO figure3a" width="550" /><br>

The final output is a 7x7x30 tensor. As we already know, 7x7 is the grid of cells laid over the image, and the 30 features hold the predicted bounding box coordinates, the class predictions, and the confidence scores. Because predictions are made relative to grid cells, the ground truth also has to be converted into grid-cell-relative values.<br><br>

For reference, in each grid cell's bounding box information, the object's center is represented relative to that grid cell, while the width and height are represented relative to the whole image.<br>

As a result, we get a tensor in which the bounding box information and class probabilities are stored longitudinally for each cell of the 7x7 grid,<br>

and these tensor values are used to compute the loss in the loss function.<br><br>
<img src="/assets/img_cv/YOLO_figure2.png" alt="YOLO figure2" width="550" /><br>

In YOLO, each grid cell is allowed two bounding boxes to capture objects. The model checks whether <span style="color:orange">the bounding box confidence score ( $Pr(Object)\cdot IOU^{truth}_{pred}$ )</span> exceeds a threshold to decide whether there is an object inside the bounding box centered in that grid cell. As the figure above shows, regardless of how bounding box localization turns out, <span style="color:orange">the conditional class probability $Pr(Class_i|Object)$ is computed per grid cell</span> for every grid cell.  
  
YOLO's loss function is an SSE (sum-squared error): a weighted sum of the squared errors of three components, namely location, confidence, and class.  

$\lambda_{coord} = 5, \ \lambda_{noobj}=.5$  <br>
$i$ is the index of the grid cell, and $j$ is the index of a bounding box whose center lies in grid cell $i$.<br><br>

>We optimize for <span style="color:orange">sum-squared error</span> in the output of our model. We use sum-squared error because it is easy to optimize, however it <span style="color:orange">does not perfectly align with our goal of maximizing average precision.</span> It <span style="color:green">weights localization error equally with classification error</span> which may not be ideal. Also, in every image <span style="color:green">many grid cells do not contain any object. This pushes the “confidence” scores of those cells towards zero, often overpowering the gradient from cells that do contain objects. This can lead to model instability</span>, causing training to diverge early on.
To remedy this, we increase the loss from bounding box coordinate predictions and decrease the loss from confidence predictions for boxes that don’t contain objects. We use two parameters, $\lambda_{coord}$ and $\lambda_{noobj}$ to accomplish this. We set $\lambda_{coord} = 5$ and $\lambda_{noobj}=.5$ .
Sum-squared error also equally weights errors in large boxes and small boxes. <span style="color:orange">Our error metric should reflect that small deviations in large boxes matter less than in small boxes.</span> To partially address this we predict <span style="color:orange">the square root of the bounding box width and height</span> instead of the width and height directly.

In the loss function above, $\lambda_{coord}$ exists to weight bounding box localization differently from classification. $\lambda_{noobj}$ exists because there will be many grid cells with no object. For those cells, only the term $\sum_{i=0}^{S^2}\sum_{j=0}^{B}\mathbb{1}^{noobj}_{i\ j}(C_i-\hat{C}_i)^2$ remains in the loss. Even when there is no object, each grid cell still predicts two bounding boxes, so the confidence score $\hat{C}_i$ gets pushed toward 0. The influence of the empty grid cells then often overwhelms the influence of the cells that do contain objects, and this weight is there to prevent that.<br>

Also, large bounding boxes (where $\hat{w}_i$ and $\hat{h}_i$ are large) can afford to be a little less sensitive to the size of the error than small ones, so the square root is taken.<br><br>

>YOLO predicts multiple bounding boxes per grid cell. At training time we only want one bounding box predictor to be responsible for each object. <span style="color:orange">We assign one predictor to be “responsible” for predicting an object based on which prediction has the highest current IOU with the ground truth.</span> This leads to specialization between the bounding box predictors. Each predictor gets better at predicting certain sizes, aspect ratios, or classes of object, improving overall recall.

Each grid cell predicts two bounding boxes ( $B=2$ ). Since one object only needs one bounding box, the one with the higher IoU is selected, its $\mathbb{1}^{obj}_{i\ j}$ is set to 1, and the loss is computed.<br><br><br>

At inference time there is no GT, so duplicate bounding boxes cannot be removed using $IOU_{pred}^{truth}$.<br>

So at inference, to remove duplicate bounding boxes, we first multiply the conditional class probability mentioned above by the confidence score to get the confidence score of each bounding box for a specific class in a grid cell (the class-specific confidence score).  

$Pr(Class_i \| Object) \cdot Pr(Object) \cdot IOU^{truth}_{pred}$    

$ = Pr(Class_i) \cdot IOU_{pred}^{truth} $

That is the formula, but as mentioned, $IOU_{pred}^{truth}$ is unknown at inference. Duplicate bounding boxes are therefore removed with Non-Maximum Suppression (NMS). Keep in mind that the IoU in NMS is computed between predicted bounding boxes, not against GT boxes.<br><br><br>

YOLO's strength is inference speed. If YOLO had also beaten Faster R-CNN on mAP, the authors would not have bothered to put it in a separate "Less Than Real-Time" category.<br><br> 

In Table 1, the authors deliberately highlight speed. Faster R-CNN at 7 or 18 frames per second is already on the slow side, and Fast R-CNN at 0.5 FPS takes 2 seconds to process a single Pascal VOC 2007 image, which is a serious problem. This gives the authors a logical basis for emphasizing YOLO's competitiveness.<br><br>
<img src="/assets/img_cv/YOLO_figure4.png" alt="YOLO figure4" width="550" /><br>
Analyzing error types like this helps in understanding and comparing the strengths and weaknesses of algorithms.<br>

YOLO had high Localization errors (correct class, but the IoU was below 0.5, so the bounding box prediction failed) and Other errors (wrong class),<br>

while Fast R-CNN was characterized by many Background errors (predicting a bounding box where there is no object).<br>

The experiment in Table 2 tests the hypothesis that Fast R-CNN could become a better model if only its background errors were reduced, and that YOLO could help with that. In other words, it is meant to indirectly verify YOLO's characteristic strength of having few background errors.<br>
<img src="/assets/img_cv/YOLO_table2.png" alt="YOLO table2" width="550" /><br>
The ensemble works by adopting a bounding box predicted by Fast R-CNN when it is similar to and overlaps with one predicted by YOLO. Several versions of Fast R-CNN were ensembled in the same way, and the ensemble with YOLO gave the largest mAP gain.<br><br> 

As mentioned above, this experiment is mainly about verifying YOLO's error profile, and it would be hard to call it a recommendation to actually use this ensemble. The ensemble runs each model independently and combines their outputs, so it cannot avoid using Fast R-CNN, which is far too slow.<br><br><br>
